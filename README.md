# Vocab Quest

把「背单词」做成能算清账的事：**今天该背几个、哪些词会忘、哪些词真记住了**，都写在一个纯静态网页里。

无框架、无构建——下载下来双击就能用，也能直接挂 GitHub Pages。页面本身零外部依赖：单词和整句发音都是站内文件（见「发音」「离线」两节），只有在站内文件缺失时才去请求词典接口兜底。学习进度默认只存本机；想看云端备份和跨设备同步，登录一下就行（这一步才用到网络，不登录完全离线可用）。

- 在线版：<https://zbqt.github.io/vocab-quest/>
- 国内备用：<https://wbapp-uugfv7gc0fmksjuo3hokye.app.workbuddy.host/?sharecode=NHL3SZEC63>（github.io 打不开时用）
- 词库：初中 1,417 · 高中 3,663 · 四级 3,737 · 六级 2,078，合计 10,895 条词条（不分大小写去重 6,369 个单词，首页显示的是这个数），全部带音标

## 它和普通背单词网页的区别

| 常见做法 | 这里的做法 |
| --- | --- |
| 每关固定考 10 题，12 个词里总有 2 个没被考到 | 每关 12 个词**全部出题**，再加 1 道语法题 |
| 星级门槛高于通关门槛，3 星永远拿不到 | 全对 3 星 / 只错 1 题 2 星 / 达到通关线 1 星，三星真的可达 |
| 答对一次就算「已掌握」 | 同一个词在 **≥3 个不同自然日、≥2 个不同方向**（认词 / 拼写 / 听音）都答对，才算进长期记忆 |
| 错词进了「巩固区」就出不来 | 错词带 `lapses / streak / dueAt`，连续答对 2 次自动退出 |
| 复习靠「今天想复习哪些」 | FSRS-5 算出每个词的到期日，只抽真正到期的词 |

## 功能

- **首页「今天 N 词」** —— 单一入口，显示今天要复习几个、学几个新词、离背完还差多少天
- **键盘操作** —— 桌面上 1-4 选选项、回车下一题、P 重听发音
- **闯关** —— 顺序 / 乱序两种模式，13 题一关（含 1～3 道语法题、2～3 道听音题、2～3 道英译中），3 条命，连对加成
- **英译中** —— 题干是英文本身，选项是四条汉语释义。其余题型全是「中→英」，方向是反的：能看着中文想起英文的人，未必能一眼认出英文，而四六级阅读考的正是后者
- **听音选词** —— 只给声音、不给词形，从 4 个英文单词里选出你听到的那个；设备放不出声就当场降级成看词选义
- **听音辨汉语（🎧 听力专练）** —— 每个单元挂一条，首页另有一个全库入口：只放声音，直接给出中文意思，不经过「先想拼写」这一步。只从**学过的词**里抽题，生词不掺进来（拿生词出听音题只能瞎蒙四选一，练的是猜运不是听力）。每次随机，反复练覆盖面会越来越大
- **听音辨汉语的两种形态** —— 入口上可选「四选一」（认出即可）或「手写汉语」（自己想得起来）。同一批词、同一套计分和星级，只换答出来的方式；默认四选一，写义要自己切过去
- **同音词不进选项** —— see / sea、peace / piece 这种（四个词库里共 106 组）声音完全一样，两个中文都算"听对了"，一道题就有了两个正确答案。出题时按音标比较键剔除；答案词本身有同音词时，答完会明说"光靠声音分不出来"
- **没出声就不算听过** —— 设备放不出声时题目会改成看英文选中文，但**不计入听力星级**，结算里写清楚哪几题没判。给掌握度注水比不练更糟
- **长对话听写** —— 12 段真实场景对话（点单、问路、选课、租房、面试、看病、改签），逐句播、逐句写，提交后按**词**标出听对 / 漏掉 / 多写，不是只给一个分数
- **长对话配音** —— 每句台词都预渲染成站内 mp3 随站点发布（74 句 / 0.93MB），同源播放、A / B 两条不同声线；手机上不需要任何语音引擎（详见下文「长对话怎么读得像人」）
- **近 7 天** —— 首页一条柱状图：哪天学了、答了几题、正确率多少，数据来自本地事件日志
- **错词重练** —— 首页直接开练答错过的词，只考认词、不扣命，连续答对两次自动移出错词区
- **词表** —— 按字母分组，点一下就读，支持搜索
- **3 分钟定级** —— 抽题估算分段掌握率，决定新词从哪一段开始学（不砍词，只排先后）
- **「这词我会」** —— 不判对错，直接推到 60 天后抽查，误点也不会漏词
- **存档导出 / 导入** —— 一个 JSON 文件，换浏览器、换设备都能带走
- **云端存档** —— 手机号或邮箱验证码登录后，学习进度自动备份到云端；换手机、清缓存都能接回来
- **装到桌面** —— 带 manifest 和 Service Worker，加进手机主屏就是一个全屏应用，断网也能接着背

> **手机端注意**：发布站不带 `?sharecode=` 会直接返回 403。所以 `manifest.webmanifest` 的 `start_url` 里写死了分享码，主屏图标点开才不会撞 403；**换分享码时这两处要一起改**。首次访问带一次分享码后，同域访问会种下 30 天有效的 cookie，期间不带参数也能开。

## 快速开始

```bash
git clone https://github.com/zbqt/vocab-quest.git
cd vocab-quest

# 音频不随仓库分发（原因见 NOTICE），需要时在本机生成：
npm run gen:words    # 单词录音 6,369 个 / 约 27MB / 十分钟左右
npm run gen:audio    # 整句人声 74 句 / 约 0.9MB / 一分钟
```

**不生成也能正常用**：页面、题库、判分、存档全都在仓库里，只是发音会退到在线词典接口，接口不通再退系统合成。断网时没有真人录音可放，仅此而已。

直接双击 `index.html` 即可（`file://` 下功能完整）。想用本地服务器：

```bash
python -m http.server 8642      # 然后打开 http://localhost:8642
# 或
npm run serve
```

### 页面「壳」的四条约定（`test/quality.test.mjs` 守着）

这几件事做错了页面照样能跑，肉眼永远发现不了，所以只能靠断言：

1. **键盘能走完**：每页第一下 Tab 是「跳到主要内容」，所有可聚焦元素有统一的焦点环（`ui.css`），不再有 `outline:none`。
2. **读屏能听见**：答题反馈是 `aria-live` 区域，两条进度条是 `progressbar` 且带 `aria-valuenow`，图标按钮都有 `aria-label`。
3. **文字看得清**：说明文字的灰度按 WCAG AA 调过（`#5f6779` 白底 5.9:1），不再用 `#9ca3af` 那种浅灰。
4. **搜索能找着**：每页有唯一 `h1`、唯一 `title`、20–160 字的 `description`、`canonical`，首页带 `WebApplication` + `FAQPage` 结构化数据，FAQ 文案必须和页面上看得见的一致。

## 数据说明

- 词库源自**有道词典公开词书**（CET4 / CET6 / 高中 / 初中），音标为美式音标。
- 公开前做过一次清洗：缺音标 208 条已补齐（148 条取自 [dictionaryapi.dev](https://dictionaryapi.dev/)，60 条人工校订）；3 个拼错的词头已修正（`reservior → reservoir`、`Rusia → Russia`、`behavious → behaviour`）。
- 语法题库共 120 道（每级 30 道），出题优先挑没做过的；做题记录存在存档里，换设备可随存档带走。
- 清洗脚本在 `tools/`：`audit.mjs`（体检缺音标/释义异常/重复）、`fill-phonetic.mjs`（补音标，结果固化进 js，运行时零请求）、`fix-zh-names.mjs`（删释义尾巴上的词典人名音译段）。
- 释义保留了原始词书的多义项内容，未做人工精简；但**删掉了词典自带的人名音译尾巴**（共 144 条，形如 `able → …；n. (Able)人名；(伊朗)阿布勒`）。这玩意对背单词没用，还会把英译中的选项撑长，一眼就能排掉。`候选人名单`、`以他人名义` 这种正常中文里的「人名」二字不碰；删完会变空释义的一律保留原样。
- **词库与音频的许可不一样，别混着用**：代码是 MIT；词库是 CC BY-NC 4.0（`LICENSE-DATA`，**禁止打包售卖**）；音频**不在仓库里**，由使用者按 `npm run gen:words` / `npm run gen:audio` 在本机生成，仅供个人学习使用，不随本项目分发。想商用请自行换成有商用授权的词库与发音（详见 `NOTICE`）。

## 装到手机桌面（推荐用法）

装好之后是：**点图标 → 点「今天 N 词」**，两次点击开始，没有地址栏，飞机上也能背。

- **iPhone / iPad**：Safari 打开线上地址 → 底部「分享」→「添加到主屏幕」
- **Android**：Chrome 打开 → 右上角 ⋮ →「添加到主屏幕」/「安装应用」

首次打开会把页面、词库、整句录音（约 1MB）缓存到本地，之后断网可用。单词录音**用到哪个存哪个**：进一组题时会把这一组 12~15 个词的音频预热下来（一次约 60KB），学过的词断网照样能听。

发布新版时改 `sw.js` 里的 `VERSION`，壳缓存自动清掉；**录音缓存（`vq-audio-v1`）刻意跨版本保留** —— 那 6 千多个词是用户一个个攒下来的，跟着版本一起清掉等于每次更新都把「离线能听」重新归零。

## 发音

**默认放词典真人录音，系统合成只作兜底。**

| 风格 | 来源 | 特点 |
| --- | --- | --- |
| 美音（默认） | **站内** `audio/w/<前两字母>/<词>.mp3` | 22kHz 单声道 24kbps，单均 4.4KB；同源、无防盗链、播过一次断网也能听 |
| 英音 | 词典接口 `dictvoice?type=1` | 英式口音，需联网（站内只有美音录音，不能用美音顶替英音） |
| 系统合成 | 浏览器 Web Speech API | 完全离线，但手机自带的英文合成音普遍机械 |

**站内录音优先。** 默认先放站内文件（同源，几百毫秒出声），文件没有（词组、生僻条目）或离线时没缓存过，才轮到词典接口，接口也不通才落到系统合成。离线时外链一路都不排 —— 反正注定失败，还要白等 4 秒看门狗。

首页（或词库页顶部）的 `🎙` 按钮循环切换，选择记在 `localStorage` 的 `vq_voice_pref`，点一下立刻试听同一个词 —— 哪种好听由耳朵定。

**三条硬规则（都是踩出来的）**

1. **录音绝不时间拉伸**。短单词做 `playbackRate=0.75`（哪怕保音调）会拉出金属味和水声，比原速难听得多；有道那条录音本身就是 1.4 秒的慢速清晰发音，再拉是负优化。所以录音恒按 1.0 播放。
2. **合成才降速**。`utterance.rate = 0.8`，比正常略慢，无副作用。
3. **失败要能降级**。录音失败（断网 / 该词没收录）→ 换另一种口音 → 仍失败 → 系统合成；反过来选「系统合成」时，合成失败也会回落到录音。没有一条路是死胡同。

`speak()` 按 `pref()` 排定通道顺序，`onFail` 逐级传递，逻辑在 `tts.js` 的 `speak / nativeSpeak / speakViaAudio`。

### 为什么单词录音要预渲染到站内

以前单词发音是**热链**词典接口：每点一次喇叭就联网一次。断网必然失败，只能退回系统合成 —— 而国产安卓机大多没装英文语音包，于是「离线 = 哑的」。

现在 `tools/fetch-word-audio.mjs` 把 6,369 个词一次性预渲染成 `audio/w/xx/<词>.mp3`（`npm run gen:words`，增量补齐，失败会落清单重试）。**但这批文件不进预缓存**：全量 28MB，让每个新用户首屏先下 28MB 不可接受。只按需下载 —— 谁播过、预热过，谁就在本地。

### 离线发音包：把「按需」的缺口补上

按需下载覆盖的是「今天要背的词」——进关卡时预热过，所以断网也能听。它覆盖不了另一种情况：**断网状态下第一次进一个新关卡**，那时一个词都没存过，全部退化成系统合成（国产安卓常常连英文语音包都没有，等于哑的）。

闯关首页因此有一个「📥 离线发音包」入口：一次把 6,369 个录音存到本机（约 27MB，建议 Wi-Fi）。它不是必选项，是给「经常在地铁/飞机上背」这种场景准备的。

- **断点续传**：每次只下缺的。中途关页面、切后台、某几个失败，下次接着补。
- **不依赖 Service Worker 是否已接管**：直接开同名缓存写，所以离线第一次打开也能用。
- **删除只删单词录音**，整句听写音频留着——用户点删除是想省空间，不是想废掉听写。
- **缓存名与 `sw.js` 的 `AUDIO_CACHE` 必须一致**，`test/offline-pack.test.mjs` 守着；改一处漏一处就会变成「下载了但播放读不到」。
- 清单 `audio-manifest.json` 只存词形（61KB），路径规则复用 `localSrc()`——存完整路径是 154KB，等于给同一件事写两个真相。

`test/tts-offline.test.mjs` 守着四件事：站内地址规则、在线时站内排第一、离线时一个外链都不排、每个词库里的词都真有对应文件（缺一个，那个词离线就哑）。

封装在 `tts.js`（`window.VQSpeech`），两个页面共用。

桌面端直接可用；手机端有几个坑，`tts.js` 已经处理：

| 坑 | 处理方式 |
| --- | --- |
| `cancel()` 是异步的，紧接着 `speak()` 新语音会被吞 | 空闲时同步调用（保住 iOS 手势上下文）；正在读时先 cancel，再让出一轮事件循环 |
| 只设 `lang="en-US"` 不指定 voice，安卓上常静默失败 | 从 `getVoices()` 里挑英文音色，优先本地 en-US；监听 `voiceschanged` 等异步加载 |
| 引擎不派发 `onstart` / 不派发 `onend` | 600ms 未启动先查 `speaking`（可能在读只是没派事件），确实没启动才恢复一次 |
| 页面切后台回来引擎被挂起 | `visibilitychange` 回前台时 `resume()` |
| 浏览器根本没有 `speechSynthesis` | 自动走录音，不再是「不支持」的死胡同 |
| 录音卡住不发事件 | 4 秒没拿到数据就换下一个源，按钮不会永远停在「播放中」 |
| 点喇叭到出声有延迟 | 题目一出现就预取该词录音（`VQSpeech.prefetch`），点下去即响 |
| 失败时没有任何反馈 | `onerror` 的错误码翻成人话：手势被拦、没装语音包、音频被占用等，直接显示在界面上 |

**手机上没声音时按顺序排查**

1. 进首页，点最下面的「🔧 没声音 / 装不到桌面？点这里」——它会列出当前浏览器、发声方式、有没有英文音色，直接说该换什么
2. **侧边静音开关**（iPhone）—— 物理静音键会连语音合成一起静音，这是系统行为，代码绕不过
3. **系统没装英文语音**：iOS「设置 → 辅助功能 → 朗读内容 → 声音」里有英文；安卓「设置 → 语言与输入 → 文字转语音」里下载（没装也能用，会自动走在线发音）
4. **在微信里打开**：微信内置浏览器对语音合成支持不稳，点右上角「在浏览器打开」
5. **刚打开就点**：部分机型首次会吞一次，再点一次即可（代码里已自动重试一次）

答题后的自动朗读不在用户手势里，iOS 会以 `not-allowed` 拦下 —— 这种失败不弹提示，喇叭按钮仍然可点。

### 发音不是装饰，是考点

发音修了三轮（原生合成 → 在线兜底 → 去时间拉伸），但如果只做「点一下听听」，用户完全可以一次都不点，那这几轮功夫等于白做。所以加了**听音选词**：

- 只播声音，**不给词形、不给音标、不给中文**——三者任一出现，这道题就等于白出
- 答完才把音标和释义摊开（学习反馈放在答题后，不放在答题前）
- **放不出声就当场降级**成「看中文选英文」。一道题因为设备没声音就变成无法作答的死题，是这条功能能不能上线的底线
- iOS 的 `not-allowed` 属于「点一下就能播」，这种**不降级**；只有 `unsupported` / `audio-unavailable` 才降级。否则 iPhone 用户永远用不上听音题
- 12 个词的关卡里出 2～3 道；每日队列里复习词每 3 个换 1 道听音，新词不考听音（第一次见就要求听音辨词是刁难）
- 答对记进 `dirs.listen`，算掌握的一个独立方向（`TYPE_DIR` 里本来就留了这个键）

### 听音写汉语：判分才是难点

「听音辨汉语」有两种形态，入口上一键切换：

| 形态 | 答什么 | 练的是 |
| --- | --- | --- |
| 四选一 | 从四个汉语释义里挑 | 认得出 |
| 手写汉语 | 自己把意思写出来 | 想得起来 |

同一批词、同一套计分和星级，`wordTypes` 只换题型；`TYPE_DIR` 把两者都记进 `listen` 方向——都是「从声音进去」，不因为要手写就另立一个能力。默认四选一：写义明显更难，该由用户自己决定什么时候上，**把默认值偷偷换掉等于在用户不知情时加难度**。

难点不在出题，在判分。词库释义是词典格式：

```
v. 丢弃；放弃，抛弃
adj. 能；[经管] 有能力的；能干的；n. (Able)人名；(伊朗)阿布勒；(英)埃布尔
```

用户听对了只会写「放弃」或「能干」。直接字符串相等必然全错，人会判到怀疑自己的耳朵。`zh-match.js` 把标准答案拆成一组**可以互换的说法**：

> 上面那条带人名尾巴的释义，现在词库里已经没有了（`tools/fix-zh-names.mjs` 删干净了）。下面第 2 步仍然保留，是给以后换词库兜底用的。

1. 剥掉词性（`n.` / `v.` / `adj.`）和学科标记（`[经管]`）
2. 人名段整段丢掉——`人名` 后面那些「(土、瑞典)安德」是音译，留着等于让人靠一个地名答对
3. 按分号和逗号拆开：「和，与」拆成两个都算对的义项
4. 比对时允许**子串**（写「能干」对「有能力的」），但长度门槛 ≥2，挡住「的」「不」这种单字乱匹配

三条边界写死在测试里：该过的必须过（第一个义项写出来一定判对，用四套真实词库跑几千条自洽检查），该拦的必须拦（写英文、写近义但没在释义里的说法，一律算错）。

另外两个只有真用起来才会碰到的坑：

- **中文输入法里回车是「确认候选词」，不是提交。** 不判 `compositionstart` / `isComposing`，刚选完第一个字就被判错。桌面端给光标、触摸设备不抢焦点——键盘一弹就把「播放」和题干顶到屏幕外，等于逼着人先猜再听。
- **放不出声时不能退成四选一**，那会顺手把难度也降了。题还是「写汉语」，只是把词形露出来当拐杖，并且不记 `listen` 方向（没出声就没有发生听觉辨认，记进去是给掌握度注水）。

### 长对话怎么读得像人

**声源换了，而且换成了站点本地的文件。** 设备自带的语音引擎是十几年前的拼接式合成，"又平又硬"是它的底子，靠调断句和音高只能修饰表面。所以每句台词都在构建时预渲染成一段 mp3，放在 `audio/<对话 id>/<第几句>.mp3`（12 段 74 句，共 0.93MB，`npm run gen:audio` 生成，**不进仓库**），练习时播的就是这个**同源文件**。

播放顺序是三级，前一级不通才走下一级：

1. **站内 mp3** —— 同源、无防盗链、无跨域、不依赖任何语音引擎，SW 缓存过一次就能离线听。
2. **第三方接口现取** —— 只有站内文件缺失（没传上去 / 改了台词没重新生成）时才用到。
3. **设备合成** —— 前两条都不通时才用，带全套断句与语气处理。

A / B 是两条不同的合成声线（`lan=en` 美音 / `lan=uk` 英音），听得出是两个人，不是一个人换个调。

**为什么非要落到文件：手机上的"没声音"几乎都出在这里。** 国产安卓浏览器（vivo / 小米 / 夸克 / QQ）很多连 `speechSynthesis` 都没有，有引擎的也常常没装英文语音包；第三方 TTS 又可能被浏览器拦掉或丢掉 `Referer` 策略。两条路一起断，用户看到的就是一句"没声音"和一个他没法执行的建议（"换个浏览器"）。同源 mp3 不受这些影响。所以「设备语音」这条兜底现在是**双向**的：人声取不到就换设备，设备读不出来就换回人声，两边都试过才认输。

这件事踩了四个坑，写下来免得重复：

1. **接口有防盗链，而且不能按元素去掉 Referer。** 带 Referer 的请求返回 `200` + 0 字节，`<audio>` 收到就报 `MEDIA_ERR_SRC_NOT_SUPPORTED`（code 4）—— 看起来像"格式不支持"，其实是没给。`referrerpolicy` 不是 `<audio>` / `<video>` 的合法属性，元素级设了不生效，只能靠文档级的 `<meta name="referrer" content="no-referrer">`，而且必须排在第一个子资源之前。测试里专门钉了这条，删掉就会红灯。这也是为什么要预渲染：抓取脚本在 Node 里跑，天然不带 Referer，不受这条限制。
2. **整句一次要，不要按气口拆。** 拆开要，每段都会被念成"一个句子的结尾"—— 段尾一律降调，连起来像一串短句，比整句更机械。暂停交给引擎按标点自己处理，比我们硬切自然。只有超过 280 字符才按句子边界拆。
3. **必须预取。** 首次点播实测要等 1.9 秒（请求 + 解码），而听写本来就要反复听同一句，这 2 秒会被放大很多次。切到某一句时先把音频取下来、点播放时复用同一个 `<audio>`，实测 `start@0ms`。
4. **单向降级在手机上等于没有兜底。** 原来只做「人声 → 设备」一个方向，而这台设备恰好是设备合成不能用的那种，于是降级终点就是静音。现在两边互为兜底，并且**记住结果**：设备读不出来就把偏好改成站内人声，不让用户下次进来再哑一次。

改了台词怎么办：

```bash
npm run gen:audio            # 幂等，只补缺的（新加的句子跑一下就行）
npm run gen:audio -- --force # 换了 spd / 音源参数才需要全量重抓
```

`test/audio.test.mjs` 盯着这件事：每句都得有文件、体积不能是空壳、mp3 头要对、不能有对不上台词的孤儿音频。这四条看起来笨，但"文件没传上去"正是最难从界面上看出来的故障——代码会一路正确降级，最后只能报"两条通道都不行"。

**代价照实说**：仓库多了 0.93MB 音频，换台词要重新生成一次；好处是手机上第一次就能出声，之后离线也能听。

**听写不能是孤岛。** 写完对一遍答案就结束，等于练了个寂寞 —— 错的词下次不会再来找你。所以提交时会漏掉的词记进 `localStorage` 的 `vq_dict_miss` 队列，回到闯关页首页时自动并进错词重练（`recordAnswer(type:"listen", correct:false)`）。

绕这一圈是故意的：存档按词书分成 4 份，**听写页不知道自己该写哪一份**，两边都写迟早结构打架。所以存档的唯一写入口仍然是 `game.html`，听写页只留话。两条克制：只收词库里真有、而且**已经学过**的词（把没背过的词塞进错词区，等于打乱新词顺序）；处理过的项标成负数，避免每次渲染首页都重复记一次 Again。

结算页还把这些词摊开成可点的标签 —— 点一下就发音。只报"你这句 62%"没有用，得让人知道具体是哪几个词没听住。

**排课上踩过的坑**：一开始拼写和听音各用模数判断（`spellEvery=4` / `listenEvery=4`），两者完全撞在同一批下标上，听音题被悄悄挤掉、一道都不出。现在改成拼写先占位，其余题型只在剩下的空位里插。

加了英译中之后又撞了一次，而且是同一类错误换个位置：听音和英译中各插各的，后来者会把前者的位置**直接覆盖**。12 个词、只剩 6 个空位、两型各要 3 道时还看不出来；空位一紧就有一型整关消失，而题面上完全看不出少了什么——你不会觉得"今天没有英译中"，只会觉得"这个 App 就是这种题"。现在两种插入题**一次算清再分配**，并且给基础题型留三分之一空位：拼写多的高等级关卡（12 词里 6 道拼写）插满之后，整关会一道"中→英"都不剩，那是写作要用的产出方向，不能整关缺席。

## 进度存储

**默认只在本机。** 存在 `localStorage` 里（各词库一个独立键，四级是 `vocabQuestV2`），不上传任何数据。旧版存档（`masteredWords` / 字符串形式的 `rescue`）首次打开会自动迁移，虚高的掌握数归零并弹窗提示。

**登录后多一份云端备份**（首页底部的「☁️ 云端存档」）：手机号或邮箱收验证码即可，不需要设密码。

| 场景 | 行为 |
| --- | --- |
| 每答一题 | 本地立刻存盘，4 秒内防抖上传一次；断网就攒在本地，下次打开补传 |
| 新设备 / 清了缓存 | 本机一个字都没学过 → 自动接上云端存档，不用点任何按钮 |
| 两台设备都有进度 | **不自动覆盖**。云端时间更晚时只提示，由你点「用云端的」或「用本机的」 |
| 没登录 / 断网 / 云端组件加载失败 | 一切照旧，只是不上传。界面会写明原因，不会假装同步成功 |

云端每个账号每个词库只存一行快照；答题日志只留最近 8 天（近 7 天视图够用，也控住存档体积）。

**云服务只在应用自己的发布域名下可用**。服务端会校验请求来源，所以 GitHub Pages、`file://`、局域网 `http://` 打开的页面登录和同步会被拒绝——本地功能照常，只是没有云端那一份。

## 已知限制

> 待办在 [BACKLOG.md](BACKLOG.md)（只放没做的事，按"能不能一天做完"分档）。
> 做过什么、当时的判断、踩过哪些坑，在 [HISTORY.md](HISTORY.md) —— 改代码前先读那里，能少走一遍老路。

- 云端同步不做实时多端合并：同一份存档在两台设备上同时改，后同步的那台会在下次同步时看到冲突提示。
- 语法题全站 120 道（每级 30 道），做完了会开始循环复用。
- 音色由系统语音引擎决定，个别 Linux 发行版需要自行安装英文语音包。
- **发音的机械感分通道**：原生合成靠手机自带引擎（多数偏机械），兜底的在线 mp3 是词典录音、单词级别自然但没有连读语调。语速统一 `0.75`（`tts.js` 顶部的 `SPEED`）。
- 词量口径：10,895 条词条是**含跨词书重复**的条数；去重后 6,369 个单词（不分大小写，`China` / `china` 记作一个）。若按原样区分大小写去重则是 6,384 —— 首页用的是前者。
